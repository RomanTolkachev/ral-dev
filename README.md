# Рабочий процесс Git

## Общее

- **Боевой сервер** соответствует ветке `master`
- **Разработка** ведется в ветке `dev`, которая соответствует тестовому серверу
- Любая новая фича разрабатывается из ветки `dev` в новой ветке
- Визуализация версии настроена через git hook на pre-commit.
В момент коммита происходит запись версии в файл version.txt, который подвязан в контроллер. 
Поэтому крайне важно следовать неймингу при заведении новой ветки.

## Соглашение об именовании веток

- `master__1.0` 
- `dev__1.1` 
- `new_feature__1.1` 
- `another_new_feature__1.1` 

### Рабочий процесс:

1. Разработка ведется в `dev`
2. Для новой фичи создается ветка из `dev`
3. После завершения - мерж в `dev`
4. После тестирования - мерж `dev` в `master`
5. Мердж обязательно происходит через merge-commit с флагом --no-ff, 

### Пример:
- `master__1.2` имеет версию **1.2**
- `dev__1.3` имеет версию **1.3**
- Новая фича будет иметь название: `new_feature__1.3`

### Формат:
- Разделитель: **двойное нижнее подчеркивание** (`__`)
- Название фичи: краткое, в snake_case
- Версия: наследуется от ветки `dev`
